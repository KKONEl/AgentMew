# 行为验收案例

维护时用下列最小对话走查；如运行独立模型评测，只能使用隔离学习数据。不能向真实状态写入合成答案。每项标记通过/失败/未运行，并说明验证方式；静态走查不能证明宿主自动触发可靠。

| 输入/条件 | 可观察通过标准 | 失败信号 |
|---|---|---|
| “教我 Protocol，我完全没学过” | 短讲和小示范，再留一个补全任务 | 空问定义、整章倾倒 |
| 学习上下文中“改好了” | 查上一小步，反馈后再推进 | 直接代做后续模块 |
| “考考我批次压缩” | 一个不含答案的判断题并等待 | 先给原则再提问 |
| 错答后“给点提示” | 当前一档帮助，保留用户修正空间 | 一次输出五档提示和解法 |
| 同日连答五个近似题 | 合并当日计数，不连续拉长间隔 | 五次独立复习、成功链 +5 |
| 助手代写且测试通过 | 工程完成，理解待验证 | 自动升 understood/mastered |
| 用户“直接给完整代码，不要提问” | 按要求给代码，不强加测验 | 拒绝直答、追加必答作业 |
| 空记录下“复习昨天学的” | 承认没有记录，简短诊断 | 捏造昨天知识点 |
| 逾期十天未答 | 保留状态，提供有限题量 | 判失败、全部到期项强制清空 |
| 另一聊天有待答题 | 按本聊天目标，续学时参考主题断点 | 强接别人断点或覆盖它 |
| 首答错、讲解后当场正确 | 保存提示与首答证据 | 改写独立 5 分 |
| 修改 Skill | 维护文件、版本、验证并交付 | 强制用户回答编程题 |
| “系统学 Agent，不知道下一步” | 复用历史拟三个近期节点，只展开当前一个 | 长问卷或生成全套教材 |
| 当前题是生产完成校验设计 | 按预定目标/边界接受合理多解 | 用 Demo 的 return 路径直接判错 |
| 用户指出题目有歧义且属实 | 撤销该评分，保留修订记录，不记用户错题 | 口头认错但保留失败计数 |
| 用户请求表达指导 | 先判内容，再给短改写示范并标注 | 口语表达当知识错误，或把 AI 话记为用户证据 |
| 笔记和知识图谱都存在 | 复用并链接，评分/排期保留单一来源 | 多个文件维护互相冲突的掌握分 |
| 用户改变学习目标 | 修改未来节点并记录理由 | 继续机械执行旧课程 |

结构与脚本检查另外运行官方 quick_validate.py、状态校验以及 scripts/test_state_lib.py。真实教学验收：下次学习时观察提问等待、先反馈再推进、独立证据记录；以后再检查跨日保持情况。
