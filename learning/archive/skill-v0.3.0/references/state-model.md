# 学习状态模型

`learning/` 中的 Markdown 是唯一学习状态来源。保持人类可读、Git 友好、短小。未知信息留空，不用推测填充。

## 文件职责

- `profile.md`：稳定背景、目标、已观察到的偏好与教学调整；不存每轮流水账。
- `progress.md`：当前焦点、下一步和精简的学习事件日志。
- `concepts.md`：每个概念一行的结构化掌握状态。
- `mistakes.md`：长期有价值的错误心智模型；每个错误一个条目。
- `review_queue.md`：由脚本根据概念和错题生成的待复习视图。
- `skill_feedback.md`：有明显信号时记录教学机制的效果。
- `archive/`：只存被保守归档的旧记录。
- `learning_path.md`：近期目标、先修与验收路径；规划状态与知识状态分开。
- `knowledge-framework.md`（已有时）：全局主题关系与证据索引；不另复制知识地图。
- `lessons/`（按需）：实际讲过的主题笔记和有价值的问答；教练概括与用户原话标明归属。
- `assessments/`（按需）：出题前的标准及作答后的证据，规则见 assessment.md。学习总结、评分和日期仍回到既有表，不建立第二套学习数据库。

新增文件均向后兼容；旧状态无需迁移，无课程/测验时不创建空目录。新的 assessment 只记录实际发生的出题，不追造历史答案标准。已完成的评测和旧版本可整体归档并保留引用；活跃错题、未答题和当前路线留在工作集。

## v0.2 证据与计数约定（2026-09-29 起）

保留原表结构、ID、旧数值和原文。旧 review_count/success_streak 可能混入同日提示练习或程序测试，不能追溯当成跨日独立证据；下次实际检验时再校准，不凭维护任务批量升降级。

- review_count 从既有值继续累计，但每个概念每天最多增加一次有效检验；同日纠错/重试合并。更新前对照 last_review 和当日进度摘要。
- 新评分保留首次尝试的质量、提示程度与迁移证据；立即照着示范复述不计独立成功。纯工程测试可以记录进度，不修改学习计数或 last_review。
- 对旧 success_streak，首次 v0.2 有效评估时重建可核实的连续链（无历史独立证据则从本次 0/1 开始），notes 标记“v0.2 已校准”。后续按复习规则更新，不能仅凭旧数值升档。
- understood 需要两次不同情境的独立成功；mastered 需要至少三个不同日期的独立成功，跨度至少 14 天，且含迁移/项目应用。它们是本系统可调整门槛，不是科学诊断；必须能在进度或归档中找到证据。
- confidence 是依据表现的教练估计；若用户自报把握，另在 notes 写“自评”，不要混为测量事实。
- 原 cause 解释也可能只是推断；不确定时标为待验证，不归因于用户人格。

## 会话接续

在 progress.md 的“会话接续”中按当前任务 ID（可得时）或用户能辨认的主题维护最多一个断点：主题、当前动作、待答问题/待改位置、提示程度、最后确认的证据、下一步、更新时间。没有待答任务就写“无”，不编造答案。

同一聊天短答优先匹配本聊天上下文；跨聊天续学参考断点，但不能擅自覆盖另一任务的未答题。只更新当前条目。每个断点保持约六行，已完成的合入主题摘要；不要保存完整对话或逐字回答。

每个学习块更新一次事件摘要，同日同主题增补原行。重复提示不追加流水。超过 30 条活跃事件或约 12 KB 时，先将原事件保留到 archive/ 的日期文件并链接，再留下阶段摘要和待验证缺口；归档不改变概念 ID、待复习条目或用户证据含义。

## 概念状态

允许值：

- `new`：已纳入计划，但尚无学习证据。
- `learning`：已接触，尚不能稳定独立使用。
- `weak`：答错、解释含糊、依赖较强提示或重复犯错。
- `understood`：至少两次在不同题型或情境中独立正确。
- `mastered`：跨至少 14 天有三次高质量回忆，并包含迁移或项目应用。

`concepts.md` 固定列：

| 字段 | 规则 |
|---|---|
| `id` | 稳定、小写 kebab-case；同义概念合并 |
| `topic` | 简短的人类可读名称 |
| `status` | 上述五种状态之一 |
| `confidence` | 0–5；表示有证据支持的独立性，不是情绪评分 |
| `first_seen` | 首次进入学习的日期 |
| `last_review` | 最近一次有效回忆或应用日期 |
| `review_count` | 有实际作答/应用的复习次数 |
| `success_streak` | 连续质量分 ≥4 的次数 |
| `interval_days` | 当前计划间隔；允许按证据调整 |
| `next_review` | 下次复习日期；无需复习时留空 |
| `related_project` | 相关文件、符号或项目场景，多个用 `<br>` |
| `common_mistakes` | 相关 mistake ID，多个用逗号 |
| `notes` | 一句话证据或边界，不写长教程 |

## 错题条目

只有会影响未来判断、设计或实现的错误才记录。错题 ID 使用稳定 kebab-case。每条包含：

- `topic`
- `question`
- `incorrect_model`
- `correct_model`
- `minimal_example`
- `cause`
- `repeat_count`
- `first_seen`
- `last_seen`
- `last_review`
- `next_review`
- `priority`：`low` / `normal` / `high` / `critical`
- `status`：`open` / `monitoring` / `resolved`
- `related_concept`
- `related_project`

同一根因再次出现：更新原条目的上下文、`repeat_count`、`last_seen`、`priority` 与 `next_review`。不要按题目表面差异制造重复条目。只有在新错误具有不同根因时才新建。

## 进度与反馈

进度日志只记录有决策价值的事件：学了什么、证据如何、下一步是什么。多次细碎事件可以合并成一条阶段摘要。

`skill_feedback.md` 只在出现明显信号时更新，例如用户明确觉得解释过长、练习难度不合适，或同一种教学方式连续有效/无效。记录证据和下一次调整，不推断性格。

## 体积控制

- 优先更新而不是追加。
- 概念 `notes` 保持一句话；详细知识属于代码、文档或课程回答，不属于状态文件。
- 每 20–30 条进度事件合并旧记录为阶段摘要。
- 只有 `mastered`/`resolved`、无待复习日期且长期未活动的记录才可归档。
- 归档前运行校验；归档动作必须可通过 Git 或 archive 文件恢复。
