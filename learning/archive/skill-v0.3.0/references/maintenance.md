# Skill Maintenance Mode

仅在用户明确要求优化、升级、复盘、修改或迭代 `learning-coach` 时读取本文件。

## 维护流程

1. 完整读取当前 `SKILL.md`、相关 references、scripts、`CHANGELOG.md`。
2. 读取 `learning/` 中近期进度、反馈、概念、错题与复习队列；只提取与 Skill 效果有关的证据。
3. 检查：冗余或冲突规则、经常被绕过的步骤、过度复杂流程、体验差的交互、无效状态字段、文件膨胀、复习选择与间隔失真、脚本和文档不一致。
4. 区分单次偶然和重复信号。优先做能解释实际问题的最小修改，不为假想边界堆规则。
5. 在动手前形成简短修改理由；若修改会删除/迁移学习数据或改变含义，先设计兼容迁移并保留可恢复副本。
6. 直接更新 Skill 和必要脚本；保持现有数据可读。允许删除、合并规则，重新设计文件结构或复习算法。
7. 运行官方 `quick_validate.py`、本项目状态校验，以及被修改脚本的边界测试；按 `behavior-checks.md` 进行情境走查，明确区分静态检查、人工走查与真实对话测试。结构通过不等于教学行为通过。
8. 更新版本与 `CHANGELOG.md`，记录日期、变更、原因和迁移说明。

## 版本规则

- PATCH：措辞、提示、校验或小型兼容修复。
- MINOR：新增模式、字段或向后兼容的行为变化。
- MAJOR：不兼容的数据结构或核心教学模型变化；必须提供迁移。

`SKILL.md` frontmatter 的 `metadata.version` 是当前版本。重要行为变化不能只写 changelog 而不更新版本。

## 维护原则

- 真实使用效果优先于初始设计。
- 不把所有用户反馈都永久固化；寻找可复现模式。
- 不为保持“完整”而保留无价值规则或字段。
- 不静默丢弃历史学习数据。
- `learning/skill_feedback.md` 是证据之一，不是唯一真相；结合实际状态变化和用户明确反馈。
- 先区分“没有触发”“触发但未遵守”“教学策略不适合”三类问题；缺少对话证据时说明不能定位每次失效。项目 AGENTS.md 只放简短触发约定，教学细节留在 Skill。
- 优化后的真实效果观察下一轮学习：是否在正确位置等待、是否根据回答调难度、是否出现跨日独立成功。没有观察前不能声称已经提高学习效果。
