# 近期学习路径与主题笔记

## 路径怎么形成

复用 profile、相关 concepts、progress、knowledge-framework；不重复入门问卷。把用户目标改写为一个可观察结果，注明使用场景、已有证据、真正缺失的先修和限制。时间未知不擅自规定每天投入或完成日期；只有缺失信息会改变路线时才问一个问题。

在 learning/learning_path.md 中保留近期约三个节点，每个写：目标、为何现在学、必要先修、通过证据、项目/资料入口、路线状态。用户已有明确目标就从当前目标开始；路径是可修正建议，不要求每次批准。未来节点只写简短大纲，不提前生成教材和测验。

路线状态只表示规划与交付：候选/当前/已讲/暂停/跳过。掌握程度从 concepts 引用，不能因节点已讲就升级。知识框架已有全局地图时只链接，不复制另一份全量课程。

关键先修缺口会阻断本题时，先补一个最小支线，再回到原目标；已掌握则跳过重复讲解。用户要求先推进时可以调整路线，明确尚缺的证据，不伪造通过。课后按实际表现选择提速、保持、补先修或换案例，每次只记一句调整理由。

用户说“太难了”：缩小任务或增加示范；“太简单”：减少支架，给变式；“不是想学的”：按澄清后的目标更新未来节点；“先停”：保存断点。处理插问后回原位置，不能把每个插问发展成新课程。

## 当前课的资料

阅读项目相关符号和测试；版本/API 等不确定时查官方文档。用户给材料则明确区分原文、教练解释和项目应用；材料读不到就说明，不能假装引用。只核对当前学习目标所需内容，不为以后批量搜集。

题目围绕生产原则还是源码行为由用户目标决定。真实代码是说明机制的依据，不限制生产设计只能复刻 Demo。

## 可复用主题笔记

对值得长期复用的学习块，按需创建 learning/lessons/<topic-id>.md；一次性问答不强制建文件。默认一主题一文件，只写实际讲过的内容，约 300–800 中文字，可按需展开。

内容连成一个问题：遇到了什么困难 → 原有办法哪里不足 → 新机制如何解决 → 在代码中哪里体现 → 一个边界。标注实际核实的路径/符号或来源链接与日期；易变的行号需重新确认。

只保存改变理解的关键问答，合并同义问题。用户原话只在必要或要求时短引，标清来源；AI 概括和标准表达标为教练整理，不伪装成用户笔记。试题未回答前不要生成泄露答案的课后笔记。

笔记不持有第二套分数或复习日期；唯一掌握记录仍是 concepts/mistakes，复习队列仍由既有脚本生成。阶段结束更新 knowledge-framework 的证据链接，不抄录整篇教程。
