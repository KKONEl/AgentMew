# 学习画像

## 目标

- 长期学习编程、项目实践、案例训练、主动回忆与系统设计。
- 重点方向：Python、Go、Java、Agent Runtime、LLM / Agent、Tool Calling、MCP、Workflow、Redis / MySQL、Docker / Kubernetes、系统设计、后端工程。
- 最终目标：能独立解释、实现、调试和做设计权衡，而不是只完成一次问答。

## 已确认的学习偏好

- 项目驱动优先，少讲空泛理论。
- 优先最小可运行案例；能结合当前项目就不使用无关玩具示例。
- 学 Python 时，在有帮助的情况下与 Java 做准确类比。
- 不要一开始给完整答案；优先让我解释、预测、修改、找 bug 或设计。
- 明显卡住时逐级增加提示。
- 复习默认加入 grill-me 式追问：沿我的回答检查因果、边界、反例和设计取舍，验证是否真懂；一次一问，不提前给答案，卡住时仍需帮助，不无限施压。
- 不过度夸奖，不频繁做无意义确认，不做冗长总结。
- 希望教学着重训练架构思维和标准化技术表达：清楚描述边界、职责、依赖、数据流与权衡；避免学生式复述和刻意堆砌术语。除非明确要求，不提供“如何向同事表达”的示范话术。
- 已明确要求在复习反馈中同时指导专业化表述：指出用词和逻辑问题，并给出简短的表达结构或改写示例；仍保留本人先作答的机会。
- 复习以生产环境的设计原则、完成判据和权衡为主；个人 Demo 只作为举例或对照，不把“描述现有代码行为”当成默认目标。
- 未提交代码可能是预留脚手架或他人/助手改动；不能据此认定用户亲自实现或掌握。优先用设计推演和用户自己的解释作为学习证据，代码归属不明确时先按参考材料处理。
- 代码指导保留一步一改，但默认提供位置、目标、约束和必要骨架，关键决定与实现由本人完成；缺基础、卡住或请求示范时再给局部代码，之后撤去帮助做变式。用户附带的其他聊天截图只作为风格参考，不自动当作当前代码修改指令。
- 独立工程思考、分步带着做和进一步追问三者都需要：先参与关键设计，再按需实现，最后用边界/故障检验；技术判断要有依据，不顺从错误观点，也不刻意反对。
- 学习阶段结束时加入阶段面试练习：优先从 `learning/interview_bank.md` 收录的小林面试笔记题目中抽取与本阶段直接相关的题，结合本项目实现追问；先让用户作答，再分析与讲解，不把题目背诵等同于掌握。题目超出当前基础时标为拓展，不强行纳入阶段验收。

## 当前水平

不作统一“零基础”判定。已有主题以 concepts 和进度中的独立证据为准；新主题未知时用一个诊断建立起点。程序通过、照写示范不等于独立能力；已证实的能力不重复用简单题校准。
