04 Agentic RAG 与 GraphRAG / LESSON 11

Self-RAG、CRAG、Adaptive-RAG 与 FLARE：信号不同，责任不同

先理解原理，再沿同一个例子看演示、读代码、运行和做变式。

建议学习 75 分钟起 · 先修：10 · 原理 → 同例演示 → 同份代码 → 练习

这一课要做到

  • 按决策位置区分四种方法
  • 知道论文复现和工程借鉴边界
  • 识别自评信号的误差

先提出四个决策问题

这些名字常同时出现，但不要背成四套完全互斥的架构。先问：什么时候需要检索？已有检索结果可信到什么程度？问题值不值得多步处理？生成到一半发现缺证据怎么办？不同工作把决策放在不同位置，并使用不同训练与推理信号。工程借鉴可以组合，但复现论文需要遵循论文定义。

Self-RAG：学习生成反思信号

Self-RAG把检索和批判信号作为特殊token参与模型学习与推理，覆盖是否检索、段落相关性、生成内容的证据支持和有用性。关键区别是这些信号经过训练，不是给任意聊天模型加一句“反思一下”就成为论文中的Self-RAG。反思token帮助选择证据和候选生成，但不会变成逻辑上绝对正确的证明。原论文

工程上可借鉴分开检查检索相关性与答案支持，但把外置LLM裁判称为“Self-RAG风格”更准确。教材把critic简化成GPT-4直接生成全部标注，会省略论文的critic学习过程；研究细节要回到论文，不能拿教学简写代替训练流程。

CRAG：先判断检索是否需要纠正

Corrective RAG重点是检索评估与补救：利用评估信号决定保留/精炼知识、补充外部搜索或采用组合策略。它是对检索失败的纠偏，不是“搜索引擎一定能兜底”。外网可能没有你的内部制度，数据还可能不可信、过期或不允许外发。生产中应该把允许的数据源、查询隐私和失败策略加入路由。原论文

知识精炼可以把长文拆成更小信息条，移除噪声，但要保留否定、时间和条件。把“除上海外均为400”精炼成“均为400”就是破坏证据。精炼结果应关联原始段落，不应成为无法追溯的新事实源。

WORKED EXAMPLE / 从刚才的原理到这份代码

检索纠偏的三分支模拟

这一节讨论CRAG式检索纠偏，下面的小实验只把“评估信号怎样变成下一动作”写成可运行规则。scores是已经给定的教学分数，不是本程序从文档里算出来的。固定四组输入依次为[0.9,0.85]、[0.1,0.2]、[0.9,0.2]和[]，因此演示和程序都只围绕这四组数，绝不突然出现内部API返回500元等未实现的数据。

先看第2行：分数全不低于0.8且列表非空，返回refine。否则第4行判断空列表或所有结果都很弱，返回fallback。剩余混合信号返回combine。你看到的三个词只是路由结果；真正精炼文档、联网搜索、再生成答案还没有执行。区分“决定去做什么”和“已经做完什么”，就是读Agent代码时必须保留的边界。

最后再看空列表：第4行的not scores or ...通过短路避免对空列表求max。边界演示故意删除not scores or，前三组仍可得到结果，第四组才报错。这样你既能把CRAG的纠偏位置与真实代码对应，也能看到一个明确的Python控制流边界。本课其余Self-RAG、Adaptive和FLARE继续作为机制对比，不伪装成这个规则函数已经实现。

对应刚才的讲解：CRAG：先判断检索是否需要纠正。本案例的运行范围：分数已人工给定，函数只决定下一动作，不实际联网搜索或训练反思模型。

完整参考实现 · 带行号供演示对照
def decide(scores):
    if all(s >= 0.8 for s in scores) and scores:
        return "refine"
    if not scores or max(scores) < 0.3:
        return "fallback"
    return "combine"

for scores in ([0.9,0.85], [0.1,0.2], [0.9,0.2], []):
    print(decide(scores))
assert decide([0.9,0.2]) == "combine"
assert decide([]) == "fallback"

Adaptive-RAG：按需要分配计算

Adaptive-RAG研究按问题复杂度选择不检索、单步或多步RAG的策略。工程关心的是路由错误的代价：把难题送单步可能失准，把简单题送多步浪费成本。路由器要在任务数据上标注和评估，不能只按问句长度判断难度。“今天汇率多少”很短却需要新鲜数据，“把上文改为三段话”很长也未必需要检索。原论文

FLARE：生成过程中的主动检索

FLARE利用即将生成的内容预测和不确定性来触发检索，再修正继续生成。低token概率只是信号，不等价于事实错误概率；罕见但正确的人名也可能低概率。API是否暴露足够的token概率、如何形成查询、如何控制检索开销，都影响能否复现。不能无条件说任何模型都能直接实现原论文机制。原论文

已解例：从故障决定借鉴哪一项

如果系统明明查到文档，却经常把不相关内容交给模型，先检查检索质量及纠偏，CRAG方向直接；如果各种题都执行昂贵多跳检索，先做路由与成本分层，Adaptive方向直接；如果长答案后半段不断增加无依据断言，可考虑分段证据检查与主动检索；如果想复现Self-RAG，需确认训练与推理能力，而不是只改prompt。

面试时先说明故障和信号，再说策略、代价与评测。例如“我在检索后检查证据是否包含金额与适用日期，缺字段则查允许的其他源；两轮仍不足就拒答”，比“我使用自我反思提高准确率”可检验得多。下面实验只模拟检索纠偏分支，不是复现任何论文，也没有训练分类器；先学会把三种结果转成明确动作。

01 · 给模型加“检查你的答案”是不是Self-RAG？

对应概念：Self-RAG：学习生成反思信号

展开参考答案与评分要点

可称通用反思或外置自评，但不等于论文里训练反思token的Self-RAG。必须区分工程借鉴与方法复现，说明用了什么信号、训练和推理过程。

检查：区分prompt与训练机制。

02 · CRAG的Web搜索能补内部报销标准吗？

对应概念：CRAG：先判断检索是否需要纠正

展开参考答案与评分要点

通常不能假设可以。私有制度可能从未公开，搜索也可能泄露查询敏感信息。只路由到授权内部源或澄清，外部信息要做信任与版本判断。

检查：不是把网络当全知兜底。

03 · “今天的价格是多少”很短，适合不检索吗？

对应概念：Adaptive-RAG：按需要分配计算

展开参考答案与评分要点

长度不是可靠复杂度/新鲜度代理。价格需时间与来源，即使语法简单也应查新鲜可信源。路由应结合任务属性、时效和风险，而不是只靠模型熟悉感。

检查：分离语义复杂度和知识新鲜度。

04 · 低token概率是否就是事实不可靠？

对应概念：FLARE：生成过程中的主动检索

展开参考答案与评分要点

不是。它表示在模型分布下的生成不确定性，罕见人名可低概率而正确，常见误传可高概率而错误。需与检索证据支持和业务字段校验配合。

检查：用至少一个反例。

容易踩的坑

  • 把所有反思都叫Self-RAG
  • 认为网络兜底总能补答案
  • 把阈值写成通用最优

这一课的验收

面对三种不同故障，先解释信号与动作，再选适合借鉴的方法。
