场景：模型接好了，服务却依然慢

一个问答服务需要从大量片段找候选，缓存重复查询，并把昂贵任务送入队列。面试官让你“先不用框架写出来”，考察的不只是语法，而是数据结构能否支撑正确契约。仓库模型与算法题涉及注意力、训练和表示评测，后端题涉及异步任务与线程池，RAG材料涉及召回和排序。本课按这些真实能力主题编写算法练习；不能由此断言某家公司逐字考过某个手写题，也不扩写成毫无边界的刷题大全。

首先把需求写清：查询是否分词、同分如何处理、k等于零返回什么、缓存是否按用户隔离、优先级数值越小是否越先、任务取消后会不会执行。没有契约的“最优算法”经常只是在优化错误问题。离线实验采用空格分词的英文token，目的是观察机制；真实中文不能直接依靠split，需要分词器、字符n-gram或其他匹配设计。

原理一：把扫描改成倒排索引

最直观的检索遍历每篇文档，统计与query重合的词。倒排索引把词映射到包含它的文档ID集合，查询只访问相关posting list。集合表示文档是否包含词，词频需要另存计数。若语料总token数为T，建索引约O(T)，索引空间取决于不同词与文档的关联数；查询成本与访问的posting总长相关，常见词会使候选接近全库，不能一律宣称O(1)。

本课用“不同查询词匹配个数”作评分，容易解释但不是BM25。BM25还考虑词频饱和、文档长度归一化和逆文档频率，能降低常见词价值。Dense retrieval即稠密向量检索，适合语义相近而词面不同的问题，但有索引构建、向量版本与资源成本。简单算法应当作为可复现基线，帮助判断复杂组件是否真有贡献。

原理二：top-k与堆的不变量

如果N个候选全部排序，需要O(N log N)时间；只保留k个时可维护大小为k的最小堆，候选扫描约O(N log k)，最后对k项再排序。最小堆的不变量是父节点不大于子节点，堆顶是当前被保留集合中最差者；若新候选更好，就替换堆顶。它不是“整个数组有序”。若你用最大堆维护候选，却没有反转比较方向，很可能留下最差k个。

同分时要指定稳定规则，比如分数降序、ID升序。实验把质量写成(score, -doc_id)，使小ID在同分下更优；最小堆顶则恰好是分数低或ID大的候选。最后排序的方向也要一致。k=0直接返回空；k大于候选数返回所有命中；没有命中不能硬塞无关文档。若ID可能是字符串，应换显式比较键，不能照抄负号技巧。

原理三：LRU是访问顺序，不是插入顺序

LRU意为最近最少使用淘汰：命中读和更新写都应把条目移到最近使用位置，满容量淘汰最久未使用者。哈希表定位配合双向链表能做到均摊O(1)的查找和移动；Python标准库OrderedDict已提供顺序与移动操作。用普通列表查找后移动可能退化为O(N)。容量零可定义为禁止缓存，负数应拒绝；不能把None作为未命中标记又允许缓存None而不加区分。

缓存正确性比命中率更优先。答案缓存键至少考虑租户、用户权限范围、查询规范化、知识版本和模型/提示版本。只用问题字符串当键，可能把A租户的片段答给B租户。TTL限制陈旧时间，LRU限制空间，两者解决不同问题，真实系统常结合；本实验只做LRU，知识变化后通过版本键隔离，不假装实现了TTL。并发访问时读后移动与写入淘汰需要同步，不能把单进程演示当成分布式缓存。

已解例：同一请求穿过三个数据结构

文档0含“agent tool policy”，文档1含“rag retrieval evidence”，文档2含“agent retrieval”。查询“agent retrieval”时文档2命中两个不同词，排第一；0与1各命中一个词，按ID先0再1，top-2是2、0。把结果存入容量2的LRU，写a和b，读取a，再写c，应淘汰b；如果仍淘汰a，说明你只记录插入顺序。

调度器接收两个高优先级任务和一个普通任务，可以用(priority, sequence, task_id)最小堆。sequence是递增入队序号，保证同优先级先到先服务，避免对不可比较的task对象做比较。任务取消通过集合标记，出堆时跳过取消项；这是惰性删除，会留下占空间的失效项，因此长跑服务需要定期重建堆。实验队列限制的是等待堆长度，明确不包含正在执行任务。满时抛出错误形成背压，而不是悄悄丢任务。

完整参考实现 · 带行号供演示对照
from collections import defaultdict, OrderedDict
import heapq

texts = ['agent tool policy', 'rag retrieval evidence', 'agent retrieval']
index = defaultdict(set)
for doc_id, text in enumerate(texts):
    for token in set(text.split()):
        index[token].add(doc_id)

def search(query, k):
    if k <= 0:
        return []
    scores = defaultdict(int)
    for token in set(query.split()):
        for doc_id in index.get(token, ()):
            scores[doc_id] += 1
    heap = []
    for doc_id, score in scores.items():
        item = (score, -doc_id)
        if len(heap) < k:
            heapq.heappush(heap, item)
        elif item > heap[0]:
            heapq.heapreplace(heap, item)
    return [-neg_id for score, neg_id in sorted(heap, reverse=True)]

class LRU:
    def __init__(self, capacity):
        if capacity < 0:
            raise ValueError('capacity must be nonnegative')
        self.capacity, self.data = capacity, OrderedDict()
    def get(self, key):
        if key not in self.data:
            raise KeyError(key)
        self.data.move_to_end(key)
        return self.data[key]
    def put(self, key, value):
        if self.capacity == 0:
            return
        self.data[key] = value
        self.data.move_to_end(key)
        while len(self.data) > self.capacity:
            self.data.popitem(last=False)

class Queue:
    def __init__(self, capacity):
        self.capacity, self.heap, self.seq, self.cancelled = capacity, [], 0, set()
    def push(self, task, priority):
        if len(self.heap) >= self.capacity:
            raise OverflowError('backpressure')
        heapq.heappush(self.heap, (priority, self.seq, task))
        self.seq += 1
    def pop(self):
        while self.heap:
            _, _, task = heapq.heappop(self.heap)
            if task not in self.cancelled:
                return task
        raise IndexError('empty')

assert search('agent retrieval', 2) == [2, 0]
assert search('missing', 4) == [] and search('agent', 0) == []
cache = LRU(2)
cache.put('a', 1); cache.put('b', 2)
assert cache.get('a') == 1
cache.put('c', 3)
assert list(cache.data) == ['a', 'c']
zero = LRU(0); zero.put('a', 1); assert not zero.data
q = Queue(3)
q.push('ordinary', 5); q.push('urgent-a', 1); q.push('urgent-b', 1)
try:
    q.push('overflow', 0)
    raise AssertionError('must reject')
except OverflowError:
    pass
q.cancelled.add('ordinary')
order = [q.pop(), q.pop()]
assert order == ['urgent-a', 'urgent-b']
try:
    q.pop()
    raise AssertionError('cancelled task ran')
except IndexError:
    pass
print('top2:', search('agent retrieval', 2))
print('LRU keys:', list(cache.data))
print('scheduled:', order)
print('edge checks: empty, zero-capacity, backpressure, cancellation passed')

在同一案例上改一个条件 1：补一条同分情况下输入顺序不同仍稳定的断言。

可以用search("tool evidence", 2)，文档0和1同为1分，断言结果为[0, 1]。再将scores遍历改为逆序，输出仍相同，因为(score,-doc_id)完整规定了同分顺序。

在同一案例上改一个条件 2：设计缓存键，避免同一问题跨租户或索引版本串用。

可使用(tenant_id, permission_scope_version, index_version, model_prompt_version, normalized_query)作为键。知识或权限变更使版本变化而隔离旧缓存，同时规划旧键过期清理。不能只把用户名字拼进query当访问控制。

边界：优先队列不等于可靠运行时

高优先级不断到来可能导致普通任务饥饿，可用aging逐渐提升等待任务的有效优先级，或分租户加权轮转。优先队列只决定开始顺序，不会抢占已经运行的长任务。持久化、租约、超时恢复、幂等与结果存储，属于可靠异步服务的额外职责。线程池最大线程数也不能代替有界队列；队列无限增大会把过载变成长尾延迟和内存问题。

算法回答应先给不变量，再给复杂度和测试反例。例如：“我用倒排降低扫描候选数，用大小k的堆筛选；最坏常见词仍可能遍历全库。缓存键加入权限与索引版本。队列同优先级稳定，满时显式拒绝，取消使用惰性删除。”最后说明数据规模和负载若改变，哪项设计先失效。面试现场可先实现正确的排序版本，再在相同断言下换堆，避免为了复杂度牺牲可验证正确性。

从反例检查实现

手写结束后，不要只打印一组正常输出。将重复查询词、完全无命中、同分文档、超过候选数的结果上限、重复更新缓存和队列满等情况逐个断言。复杂度讨论也要指出变量是什么：语料总词数、命中文档数、保留结果数与等待任务数不能混用同一个N。若需要测性能，用固定随机种子构造不同规模的输入，分开统计建索引和在线查询时间；微小数据的偶然耗时差不构成速度提升证据。先保证输出相同，再比较资源，才能把优化与改变任务偷偷混在一起的错误排除掉。

01 · top-k为什么用最小堆，堆顶保存什么？

对应概念：原理二：top-k与堆的不变量

展开参考答案与评分要点

当我们要保留最大的k个分数时，最小堆顶是已保留集合中最差者，新候选比它好才替换。扫描N项需O(N log k)，输出有序结果另需O(k log k)，空间O(k)。同分规则必须进入比较键，否则输入顺序变化可能改变输出。若k接近N或数据很小，直接排序更简单，不能只追求渐近表达。

检查：3分：不变量、复杂度、同分/取舍各1分。

02 · LRU缓存为什么不能只按写入时间淘汰？

对应概念：原理三：LRU是访问顺序，不是插入顺序

展开参考答案与评分要点

LRU按最近访问，读命中也应移动；只按写入顺序更像FIFO。哈希表与双向链表支持O(1)定位和移动。TTL处理陈旧，LRU处理空间；多租户答案还必须把权限与知识版本放入键，迁移到线上需考虑并发和失效策略。

检查：3分：读更新、结构复杂度、正确性边界各1分。

03 · 优先级队列保证所有任务最终执行吗？

对应概念：边界：优先队列不等于可靠运行时

展开参考答案与评分要点

不保证。高优先级持续到达可使低优先级饥饿，同级也需序号保证稳定。可用aging或分租户公平调度，但会增加策略复杂度。队列还不提供持久化与幂等，Worker崩溃需租约恢复；有副作用任务不能靠简单重新出队实现exactly-once。

检查：3分：饥饿、策略取舍、运行时边界各1分。

04 · 词法检索实验结果很好，是否可以替代向量检索？

对应概念：原理一：把扫描改成倒排索引

展开参考答案与评分要点

只能说明该小语料与查询上有效。词面不重合、同义表达和多语言问题可能漏召回；先建立含相关证据和难负例的隔离集，比较Recall@K、排序和端到端成功率。词法更可解释且成本低，向量可补语义召回；采用混合前要做消融，不能把重合计数宣称BM25或生产最优。

检查：3分：分布局限、评测、取舍与命名准确各1分。
