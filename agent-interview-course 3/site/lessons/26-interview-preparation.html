场景：看完面经会背，却经不起第二个问题

你能解释RAG和ReAct，但面试官追问“你说成功率提高，样本从哪里来”“如果请求执行成功但响应丢失怎么办”，就只能重复术语。这说明需要补的是证据与因果链，不只是更多名词。本课将课程实验组织成可展示材料，再通过阶段模拟暴露缺口。完成练习能帮助准备面试，不能保证录用；岗位要求、招聘流程和评判偏好会变化，离线材料只代表保存时的来源快照。

先辨别来源，再决定怎么练

公司官方岗位描述能说明某个职位在某时点公开表达的要求，不能证明所有团队都问同样问题。公开面经是作者描述的经历，可能记忆有误或缺少上下文；聚合平台转述更需要核验；编辑改写题是训练材料，不是官方题库或标准答案。仓库中2026-10批次明确区分B类曾定位原帖与C类待核验聚合线索，B也不自动证明作者亲历或全文可信。公司标签表示相关主题报道，不表示逐题真实归属。

使用方法是从多条独立来源提取能力主题：检索评测、恢复幂等、工具权限、项目设计等，再映射到已做实验。不要背“某公司必考某框架”，也不要把跨公司矩阵里的推断写成招聘事实。若面试需要最新岗位细节，应查看该岗位最新官方信息；本离线站不自行刷新，也不把历史描述包装成最新状态。对未核验说法保留“报道、线索、编辑归纳”的措辞。

STAR不是编故事，而是索引证据

S是Situation，说明用户与具体问题；T是Task，说明你的职责和约束；A是Action，说明你做了什么以及为什么；R是Result，说明怎样验证、结果是什么和仍存风险。把篇幅更多留给Action中的因果选择，避免用大量背景遮住自己没有做的部分。团队成果要区分“团队实现”和“我负责”，教程实验则如实称个人练习或离线原型。

例如：“在个人离线文档问答练习中，我要验证租户隔离与拒答。我先写五类固定用例，再将权限过滤放在召回前，输出文档版本与引用。运行五条断言全部通过，并另加跨租户额度不串用检查。它只验证这组确定性样例，尚未测试真实PDF、向量检索和并发。”这段没有耀眼的虚构数据，却明确提供问题、行动、证据与范围。若将5/5写成‘系统准确率100%’，就把极小的教学覆盖错误外推到生产能力。

结果数字必须带分母、时间窗口、基线、配置和方法。准确率从70%到80%，是10个百分点而非10%相对提升；相对提高约14.3%。P95应说明请求样本与统计方式，不能拿三个请求的最大值装作稳定尾延迟。没有真实业务用户时，不编造请求量、营收或效率倍数，可以报告可复现实验、故障注入和已知边界。助手给出的示例与代码运行证据，也不能自动当成你独立完成的学习证据。

已解例：八条评分记录如何形成复习路径

为了把“需要复习”变成具体行动，实验固定八条Record，分别对应architecture、retrieval、recovery、security、collaboration、training、STAR和failure。score来自假设的人工评分，evidence是引用字符串，revisit是建议课程；它们不是程序根据面试音频自动识别的结果，更不代表你的实际水平。

effective_score先拒绝零到三之外的分数；若证据字段为空，最高只能算二分。这条规则不会验证引用真假，只阻止空证据直接取得三分。八条记录相加得到十三分，其中检索、恢复和训练各一分，其余各二分。critical_ok要求安全与恢复都至少二分；恢复只有一分，所以即使以后其他题提高，总分条件也不能代替关键能力门槛。当前ready_for_next_mock为False。

weak筛出低于二分的记录，按分数与topic字符串排序，依次打印recovery、retrieval和training的复习课程。你可以从恢复题开始，回到15、16课补一个“服务端已执行但客户端超时”的反例，再将真实证据引用写入对应记录。正常演示只推导当前八条数据；失败演示放大代码已有的Record('test',3,'','21')，说明声称三分而缺证据时会被降为二分。程序并没有完成复习或重新面试，这些行动需要你实际执行后另行记录。

阶段模拟：按证据评分，不按话术评分

本课八题覆盖架构、检索、恢复、工具安全、多Agent、训练、项目与失败。建议先用两分钟介绍真实项目，再逐题用九十秒回答，最后做十分钟手写或实验修改。每题按0至3分：0分为概念错或无答案；1分能说正常机制；2分能说边界、取舍与可执行验证；3分在上述基础上提供真实可追溯证据或完整可运行反例。参考答案是回答方向，不是你已取得3分的证明。

总分24可以作为练习进度，不作为录用概率。建议自定18分作为继续综合模拟的门槛，同时权限与恢复题不能低于2分；这是教学建议。若低于门槛，选最低的一题回对应课程重做实验并补一条反例，再换输入复测。评分应尽量请同伴按相同rubric盲评，避免“看到答案后觉得我本来就会”。自评记录要保留原回答、证据链接、缺口和复测日期。

WORKED EXAMPLE / 从刚才的原理到这份代码

八条Record的13/24评分与复习清单

前面讲来源可信度和真实STAR表达，下面把“按证据找缺口”落实为实验里的八条Record。records写明每题的topic、人工给定分数score、证据引用evidence和复习课程revisit；代码不会读懂你的口答，也不会自行鉴定引用真实性。

你先按effective_score检查分数范围和空证据封顶规则，再跟随scores与total手工相加，确认当前是十三分而非凭感觉判断“准备好了”。随后critical_ok单独检查安全与恢复两题，恢复一分使关键门槛失败，ready_for_next_mock因此为假。最后weak把三项低分按主题名排序，打印恢复、检索、训练各自对应的课程。

演示中的正常路线始终使用这八条固定数据；失败路线只放大原程序已有的三分空证据断言，该独立记录不会加入总分。这样每个数字、排序和复习入口都能回到代码，而不是把一段面试故事当成算法输出。你真正需要做的下一步，是先独立口答，再把真实评阅与证据替换进记录，完成一条新反例后重新测量；脚本本身不会替你完成这些学习行动。

对应刚才的讲解：阶段模拟：按证据评分，不按话术评分。本案例的运行范围：分数和证据由学习者给定，程序只生成复习清单，不自动判断口答质量。

完整参考实现 · 带行号供演示对照
from dataclasses import dataclass

@dataclass(frozen=True)
class Record:
    topic: str
    score: int
    evidence: str
    revisit: str

records = [
    Record('architecture', 2, 'workflow comparison notes', '03,11,24'),
    Record('retrieval', 1, '', '07-10,24'),
    Record('recovery', 1, '', '15,16'),
    Record('security', 2, 'tenant isolation asserts', '18,20,24'),
    Record('collaboration', 2, 'gate stdout', '11,19,25'),
    Record('training', 1, '', '21'),
    Record('STAR', 2, 'project card with denominators', '24-26'),
    Record('failure', 2, 'before-after failure fixture', '19,20,25'),
]

def effective_score(record):
    if record.score not in range(4):
        raise ValueError('score must be 0..3')
    # A top score requires an evidence reference; this does not verify the evidence itself.
    return min(record.score, 2) if not record.evidence.strip() else record.score

scores = [effective_score(r) for r in records]
total = sum(scores)
critical_ok = all(effective_score(r)>=2 for r in records if r.topic in {'security','recovery'})
ready_for_next_mock = total >= 18 and critical_ok
weak = sorted((r for r in records if effective_score(r)<2), key=lambda r:(effective_score(r), r.topic))
assert total == 13 and not critical_ok and not ready_for_next_mock
assert effective_score(Record('test', 3, '', '21')) == 2
print(f'mock score={total}/24; critical topics ready={critical_ok}; next mock={ready_for_next_mock}')
for r in weak:
    print(f'revisit {r.topic}: lessons {r.revisit}; add one counterexample and evidence')
print('Teaching rubric only; no hiring probability is estimated.')

在同一案例上改一个条件 1：总分19但恢复题1分，应继续什么？

按照示例规则critical_ok仍为False，不直接进入综合晋级。先回15、16完成请求已执行但响应丢失的故障注入，记录幂等查询与恢复输出，再换新输入复测恢复题；不要用高分概念题抵消关键风险。

在同一案例上改一个条件 2：如何防止看到答案后自评虚高？

先限时录下原答，隐藏参考答案；请同伴按相同rubric盲评，3分必须检查可追溯证据与新反例。复测使用不同输入和追问，并分别记录独立回答、参考答案学习和助手示范，避免把熟悉度当掌握。

压力面试中的沟通顺序

先澄清题设与约束，再给最小方案，解释关键取舍，最后用证据和边界收束。被打断时先回答新问题，不急着把背稿讲完；不同意假设时用具体反例，比如“请求超时但服务端已提交，直接重试可能重复付款”。遇到不会的细节可说“我没有验证该版本API，我能先说明恢复应满足的不变量，再查文档或设计最小实验”。这让不知道与没有思考分开。

反问聚焦真实工作：业务成功如何定义、哪些操作允许自动执行、谁维护评测、发生回归怎样回滚、团队主要瓶颈是什么。不要把追问当套取内部机密，也不要仅凭一次交流推断组织整体文化。面试后记录不涉及机密的能力缺口，回到项目补证据，而不是无限收集更多面经。

简历与交付材料

准备一页项目卡、架构图、能运行的最小样例、固定数据版本、真实测试输出、一条失败及修复对照、已知限制。简历每项成果都能对应材料；不会展示的商业敏感资料用合成数据复现机制，并说明脱敏。实验扩展题做完后记录哪些是独立完成、哪些参考答案或助手示范，再决定下一阶段能力。最后用一分钟表达问题、责任、方案、难点、验证与风险，做到被追问时能回到具体输入、状态和输出，而不是框架名称。

01 · 模拟1：为什么业务需要Agent，而不是普通工作流？

对应概念：阶段模拟：按证据评分，不按话术评分

展开参考答案与评分要点

先明确任务是否有运行时的语义决策：若只是固定检索、格式化和审批，工作流通常更可控；若需要基于新证据动态澄清、选工具或分解任务，才给模型有限决策空间。建立固定流程与单Agent基线，用经验证成功率、延迟、成本和失败分桶比较；必要时退回简单方案。真实证据应来自自己的相同任务对照，不可把课程示例当线上结果。

检查：0：把Agent等同聊天；1：描述动态决策；2：给边界和基线；3：有真实对照或可运行反例。失败路径：复习03、11、24，画出确定性步骤与模型决策点。

02 · 模拟2：RAG答案错误，怎样定位？

对应概念：阶段模拟：按证据评分，不按话术评分

展开参考答案与评分要点

沿解析、切片、权限、召回、重排、上下文与生成逐层检查。先确认原文确有有效答案，再看相关证据是否进入候选与最终上下文；替换为人工正确证据做oracle对照，区分检索与生成瓶颈。固定数据和提示，保留失败样本与引用版本；不能因为答案流畅或带引用就算对。

检查：0：只说换大模型；1：能列链路；2：给oracle与控制变量；3：展示实际候选/引用/失败回归。失败路径：复习07-10、24，给实验新增冲突证据用例。

03 · 模拟3：写入工具超时后能否直接重试？

对应概念：阶段模拟：按证据评分，不按话术评分

展开参考答案与评分要点

不能从客户端超时推断未执行。先按幂等键查服务端结果或任务状态，已完成则复用；未完成或可安全重试时有界重试。调用意图、请求ID与结果要持久化，恢复时关联同一意图；高风险操作保留审批，无法判定时转人工，避免重复副作用。幂等还需业务唯一约束与保留窗口支持。

检查：0：无限重试；1：知道有重复风险；2：完整查询/幂等/恢复方案；3：有响应丢失故障注入证据。失败路径：复习15、16，验证“已执行但响应丢失”反例。

04 · 模拟4：恶意文档让Agent发送全部资料怎么办？

对应概念：阶段模拟：按证据评分，不按话术评分

展开参考答案与评分要点

把文档与工具返回视为不可信数据，不能提升为系统指令。执行器依据用户身份、任务scope、工具allowlist和参数校验授权；检索前过滤租户与权限，写入及外发需要相应审批。输出、日志和模型上下文也要遵守数据边界，并将注入与越权加入Safety回归。提示文字只能补充，不能代替服务端控制。

检查：0：只加“忽略注入”；1：识别不可信输入；2：多层执行控制；3：有越权拒绝及无泄露断言。失败路径：复习18、20、24，改造一条跨租户攻击测试。

05 · 模拟5：两个研发Agent都同意代码正确，可以合并吗？

对应概念：阶段模拟：按证据评分，不按话术评分

展开参考答案与评分要点

不能。先检查它们是否基于同一需求和提交，是否独立审查而非互相引用结论。核对diff、测试命令、真实输出和最终环境，整合后重新验证接口。多Agent适用于可分工任务，仍会有共享盲点与沟通成本；关键安全违规一票否决，自动生成patch只作为待审产物。

检查：0：多数同意即合并；1：知道要测试；2：完整证据和整合方案；3：能运行门禁并解释失败传播。失败路径：复习11、19、25，构造Outcome成功但Trajectory失败。

06 · 模拟6：LoRA、QLoRA、SFT、DPO如何组织？

对应概念：阶段模拟：按证据评分，不按话术评分

展开参考答案与评分要点

SFT是监督目标，LoRA是低秩可训练增量，QLoRA增加量化基础权重的存储策略，DPO利用偏好对相对参考策略优化。它们不全互斥。先确认是行为还是知识问题，再评估数据与收益；显存分权重、梯度、优化器、主副本、激活与临时空间。没有真实GPU训练就只陈述机制实验与预算下界。

检查：0：混为一谈；1：基本定义；2：三轴区分及资源边界；3：算对非方阵参数并给独立评测设计。失败路径：复习21，更换矩阵尺寸重新手算。

07 · 模拟7：用STAR介绍你的项目，数字怎样可信？

对应概念：STAR不是编故事，而是索引证据

展开参考答案与评分要点

S讲真实用户或离线实验背景；T讲个人职责与约束；A解释为什么这样设计并给关键操作；R给分母、版本、基线和测量方法，附失败及边界。若只有五条固定断言，就说五条断言通过，不能写生产准确率100%。团队成果与个人贡献分开，教程参考与独立实现分开。

检查：0：虚构或无职责；1：有四段结构；2：因果与测量边界清楚；3：每项结果有可追溯真实材料。失败路径：复习24-26，制作一页项目卡并核对每个数字。

08 · 模拟8：项目最失败的决策是什么，如何证明修复有效？

对应概念：已解例：八条评分记录如何形成复习路径

展开参考答案与评分要点

选真实发生且自己理解的失败，描述错误判断、影响、发现线索、根因、替代方案、对照验证和残余风险。例如权限后置导致授权证据被挤掉，前置过滤后用固定跨租户样例验证，并补缓存权限版本。若只是分析案例，明确称案例，不编造成线上事故；修复一次还要把最小失败加入回归。

检查：0：没有失败或归咎AI；1：描述现象；2：有根因与验证；3：真实前后证据、回归与未解决风险。失败路径：复习19、20、24、25，从日志找第一个出错环节。
