场景：工具格式总错，是否需要训练

你为文档助手接入一个只接受结构化参数的查询工具，模型经常把日期写成自然语言。先保存失败输入、输出、Schema 校验结果，判断失败发生在模型输出还是解析器。若 Schema 有歧义，先修契约；若少量示例与约束解码能解决，不必立即训练。知识经常更新时检索更容易更新和撤回；稳定的工具调用习惯、回答风格和领域表达，才是监督微调可能改善的对象。训练并不能自动获得最新文档，也不能取消服务端权限校验。

必须区分三条彼此正交的轴：SFT、DPO、PPO回答“优化什么目标”；全参数、LoRA回答“哪些参数可更新、如何表示更新”；FP16、BF16、4-bit量化回答“数值怎样存储和计算”。所以可以用LoRA做SFT，也可以使用低秩适配器做偏好优化，不能把它们当互斥菜单。

原理：从下一个 token 到行为改变

Token是模型处理的离散单元，未必等于一个汉字或一个单词。因果语言模型依照输入与已有输出预测下一个token。Transformer中的注意力常写成 softmax(QKᵀ/√d_k)V：Q是查询向量，K是键，V是值，缩放帮助控制点积分布。多头把表示投影到不同子空间，不保证每个头都天然学到一种人类可命名的语义。模型训练需要数据、目标、可训练参数、优化器和评测共同成立。

SFT即监督微调，以高质量输入与目标回复为示例，降低正确回复token的负对数概率。常见指令训练只对assistant回复计算损失，这叫loss mask；但并非所有SFT定义都要求完全相同的mask策略。多轮训练要说明哪些assistant轮参与目标，工具结果是否当条件，padding是否被排除。若答案概率从0.2提高到0.5，对该token的负对数损失会下降；这只说明更贴近标注，不能直接等同业务成功率上升。训练和验证都包含同一模板的近重复样本时，低loss还可能来自泄漏。

LoRA即低秩适配。原权重W形状为d×k，冻结W，仅训练A（r×k）与B（d×r），使用 W + (α/r)BA，r通常远小于d、k。训练参数从dk变为r(d+k)。低秩是对可学习更新的结构约束，不是把整个基础模型删小。常见初始化令一侧为零，使初始增量为零；反向传播仍会逐步更新适配器。rank提高增加容量与开销，也可能过拟合，必须和目标层、数据量、学习率一起验证。合并适配器便于推理，但多租户需要保存基础版本和适配器兼容关系。

QLoRA常将基础模型以低比特量化保存，计算时按所需精度反量化，梯度主要更新低秩适配器。4-bit是权重存储位宽的一个近似预算，不代表所有激活、梯度、优化器状态都变成4-bit，也不意味着模型参数数目减少。量化有分组尺度、元数据与误差，不能直接拿“参数×0.5字节”宣称实际峰值显存。

已解例：把数字拆成可审计假设

一个4096×4096投影矩阵有16,777,216个权重；rank为8时，A与B一共65,536个参数，比例为0.390625%。这里仅计算一个投影，整模型需按每层每个目标矩阵累加，不能把这个比例套给所有架构。实验会真的构造2×2矩阵和rank-1增量验证前向结果，同时计算大矩阵参数量；它没有训练模型，也没有测真实GPU内存。

显存预算至少分权重、梯度、优化器状态、可能的FP32主副本、激活、临时buffer、通信和碎片。若假设70亿参数，BF16权重2字节、梯度2字节、Adam的两个FP32动量8字节、FP32主权重4字节，则仅这些项目合计16字节/参数，即112GB十进制，尚未计激活；某些实现不保留同样的副本，不能说16是普适常数。冻结的权重通常不需要对应梯度和优化器状态，但前向、反向相关激活仍可能很大。梯度检查点用额外重算换激活显存；梯度累积减小单步micro-batch却不能消除权重占用。有效batch还要结合数据并行副本数，而不能把张量并行卡数直接算进去。

偏好优化：会模仿不等于会选择

DPO使用同一提示下的偏好对：chosen与rejected，通常相对于一个固定参考策略比较两段回复的对数概率差，用逻辑损失增加偏好回复的相对优势。它不要求像典型PPO训练那样在训练循环里反复在线采样并单独拟合价值模型，但仍需要可信偏好数据、参考约束和验证。偏好标注若只奖励长答案，模型可能学会啰嗦而非更正确；风格偏好也不能代替工具结果验证。

PPO是近端策略优化，常在RLHF中使用：策略采样回复或轨迹，奖励模型或可验证结果给分，价值估计构造优势，clipped surrogate限制某些过大的策略更新，并常配合参考策略KL约束。优势表示相对预期的好坏；它不是原始奖励的同义词。clip也不提供绝对安全保证。长任务只有最终奖励时，信用分配很难：最后成功可能依赖早期一次正确检索，错误动作却也可能被一同强化。PPO增加在线采样与多模型管理成本，DPO的离线偏好对也可能不能覆盖新策略遇到的分布。

WORKED EXAMPLE / 从刚才的原理到这份代码

手算低秩前向、参数预算和DPO标量

本课先区分训练目标、可训练参数和数值存储，下面把这三条轴落在同一份机制脚本上。脚本并不接入语言模型：先用二乘二单位矩阵w、输入x以及一对秩为一的矩阵a和b，逐步得到base、delta和y。你可以手算出输入二与三经过增量路径变成十与负五，再对照断言，而不是只记住“低秩更省”的结论。

随后脚本只更换计数变量d、k和rank，计算四千零九十六维投影的参数比例，没有真的创建或训练大矩阵；再用n和static记录七十亿参数的静态字节假设。最后chosen_logp、rejected_logp与参考概率形成margin，说明偏好方向怎样改变一个标量损失。

演示按代码的五个计算阶段前进，正常结果全部可在打印输出中核对；失败分支明确换成维度不兼容的单独调用，查看matmul已有的断言如何拦截。三个子实验共享的是计算机制与审计假设，不表示训练流水线已经执行。请特别区分手算结果、机制断言与真实训练证据，后者在本实验中并不存在。

对应刚才的讲解：偏好优化：会模仿不等于会选择。本案例的运行范围：小矩阵和标量用于核对训练机制及预算，不实际训练模型。

完整参考实现 · 带行号供演示对照
import math

def matmul(a, b):
    assert a and b and len(a[0]) == len(b)
    return [[sum(x*y for x,y in zip(row,col)) for col in zip(*b)] for row in a]

w = [[1, 0], [0, 1]]
a, b, x = [[1, 2]], [[1], [-1]], [[2], [3]]
base = matmul(w, x)
delta = matmul(b, matmul(a, x))
y = [[p[0]+q[0]] for p,q in zip(base, delta)]
assert y == [[10], [-5]]
d = k = 4096
rank = 8
full, lora = d*k, rank*(d+k)
assert lora == 65536 and lora < full
n = 7_000_000_000
static = n*(2+2+8+4)
quantized_weight_lower_bound = n/2
assert static == 112_000_000_000
chosen_logp, rejected_logp = -2.0, -4.0
ref_chosen, ref_rejected, beta = -3.0, -3.0, 0.1
margin = beta*((chosen_logp-rejected_logp)-(ref_chosen-ref_rejected))
loss = math.log1p(math.exp(-margin))
assert loss < math.log(2)
print('rank1 forward:', y)
print(f'full={full} lora={lora} ratio={100*lora/full:.6f}%')
print(f'assumed static training={static/1e9:.1f} GB; no activations included')
print(f'4-bit raw weights lower bound={quantized_weight_lower_bound/1e9:.1f} GB')
print(f'DPO pair loss={loss:.6f}; baseline={math.log(2):.6f}')

运行后应看到

rank1 forward: [[10], [-5]]
full=16777216 lora=65536 ratio=0.390625%
assumed static training=112.0 GB; no activations included
4-bit raw weights lower bound=3.5 GB
DPO pair loss=0.598139; baseline=0.693147
在同一案例上改一个条件 1：把rank改为16，参数占比如何变化？

r=16时为131,072个参数，占0.78125%，恰为原来的两倍。基础权重不变；真实峰值不会严格翻倍，因为基础权重和部分激活没有随rank同比变化。

在同一案例上改一个条件 2：若chosen/rejected相对于参考的优势交换，损失会怎样？

margin由0.2变为-0.2，损失log(1+exp(0.2))约0.798139，大于中性0.693147。模型被惩罚是因为它相对于参考更偏好被拒回复，而非因为回复绝对概率必须超过0.5。

边界与技术表达

评测至少包含格式有效率、工具执行成功率、答案证据一致性、通用能力退化、成本与延迟；保留未见任务与拒答样本。按来源或时间拆分，避免同一用户问题改写跨集合。对比prompt基线、相同数据预算的SFT、不同rank，记录训练版本及失败样本。训练集变好而独立集不变时，先检查过拟合、标注冲突和目标错配。

面试可以这样说：“我先通过Schema和few-shot建立基线，确认残余错误是稳定行为问题，再选LoRA控制可训练状态；显存给出每项假设而不是固定口号。用隔离测试集比较工具成功率与遗忘，若收益不足则保留更简单方案。”没有做过真实训练，就明确说“我实现了机制与预算实验，尚未验证硬件峰值和训练收益”，这比虚构模型名称、训练卡数和提升比例更可靠。

01 · SFT、LoRA、QLoRA分别解决什么问题？

对应概念：原理：从下一个 token 到行为改变

展开参考答案与评分要点

SFT规定学习目标：用标注回复做条件语言建模；LoRA用低秩增量限制可训练参数；QLoRA再用量化基础权重节省存储。因此LoRA不是一种损失函数，QLoRA也不是所有状态都4-bit。工具格式任务可先做LoRA-SFT，但权限必须由执行器校验；若问题是新知识更新，应优先检索。

检查：3分：三轴区分、可组合、任务迁移各1分。只背“节省显存”最多1分。

02 · 4096×4096矩阵，rank=8的LoRA有多少参数？能推算整模型显存吗？

对应概念：已解例：把数字拆成可审计假设

展开参考答案与评分要点

基础矩阵4096²=16,777,216，适配器8×(4096+4096)=65,536，即0.390625%。只能得到该投影的参数比例；整模型必须枚举层、目标矩阵、基础精度、可训练状态、激活和临时空间。长上下文会增大激活，因此参数少也可能OOM。

检查：3分：数量、比例、整模型/激活边界各1分。

03 · 何时考虑DPO，何时考虑PPO？

对应概念：偏好优化：会模仿不等于会选择

展开参考答案与评分要点

已有高质量同提示偏好对时，DPO可在离线数据上提高相对偏好，并减少典型在线RLHF的系统复杂度。若任务可交互、有可验证奖励且需要探索新轨迹，可研究PPO，但要预算采样、价值估计和KL约束成本。二者都不能自动修正有偏奖励；工具任务应把外部成功和安全约束纳入验证，先建立SFT与检索基线。

检查：3分：数据与交互前提、系统代价、奖励边界各1分。

04 · 训练loss下降，工具成功率不升，怎么排查？

对应概念：边界与技术表达

展开参考答案与评分要点

先查评测独立性与标注质量，再分层观察格式有效、参数语义、工具成功和最终任务成功。若格式正确但工具拒绝，可能是Schema版本或权限问题；若只见过模板有效，则可能过拟合。冻结工具版本，用同一测试集比较prompt基线与训练模型，增加难负例或调整目标，而非盲目加epoch。

检查：3分：分层定位、独立对照、因果修正各1分。

容易踩的坑

  • 把SFT与LoRA当互斥方案
  • 把4-bit权重下界当整机显存峰值
  • 拿训练loss代替独立业务评测

这一课的验收

不看答案算对一个非方阵的LoRA参数量，解释显存四个以上组成项，并用独立评测说清是否需要训练。
