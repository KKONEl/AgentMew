99. 给定日请求量、每任务工具次数和延迟，如何估算并发需求并说明假设？

题目 ID：Q-29bf58eb3163 · 编辑难度：hard

相关主题的报道公司（非逐题归属）：字节跳动

参考答案

先用到达率 λ 与平均在途时间 W 估算 L=λW。举例：日10万任务、每任务串行5步、每步0.8秒模型加0.2秒工具，则全天均匀平均约5.8个在途任务；峰值与尾延迟另算。

得分点

  • 模型/工具配额分别核算
  • 声明并行、到达分布及利用率假设

追问：如果0.8秒是每任务一次而非每步一次，结果如何变化？

易错点：平均并发不是所需机器数，更不是峰值容量承诺。

面经主题线索：INT-2bfa666e65（B：曾定位公开原帖）

答案机制资料：未单列外部机制资料，属于编辑推导，须结合具体契约独立验证。

100. 上千个代码执行沙箱同时活跃时，你会怎样设计资源池和调度策略？

题目 ID：Q-217a9345a3b4 · 编辑难度：hard

相关主题的报道公司（非逐题归属）：小米

参考答案

先按任务隔离与资源规格做池化，设置租户配额、队列、公平调度和并发上限；热池改善启动延迟，强清理或重建防状态残留。按 CPU、内存、进程数和网络分别限额。

得分点

  • 拒绝或排队优于无限超卖
  • 空闲回收并可观测

追问：恶意租户持续占满资源池怎么办？

易错点：1000个沙箱不能直接换算为1000核，需按实测负载规划。

面经主题线索：INT-91419e91fb（B：曾定位公开原帖）

答案机制资料：SANDBOX：gVisor architecture guide

101. 端到端耗时上升时，怎样拆分模型、检索、工具及调度各段的贡献？

题目 ID：Q-1fdfe4f59d0b · 编辑难度：hard

相关主题的报道公司（非逐题归属）：字节跳动

参考答案

用同一任务 trace 标记排队、模型、检索、工具及提交耗时，重试和并行分支单独统计；端到端看关键路径而非把重叠 span 全相加。按版本、场景和尾分位定位变化。

得分点

  • 区分服务等待与实际执行
  • 控制时钟和采样影响

追问：平均变好但 p99 变差怎么解释？

易错点：总耗时不能简单等于所有子调用耗时之和。

面经主题线索：INT-340e4aa1be（C：仅聚合线索）

答案机制资料：未单列外部机制资料，属于编辑推导，须结合具体契约独立验证。

102. 降低 Token 费用时，怎样同时证明质量没有明显退化？

题目 ID：Q-a417916ecd0d · 编辑难度：medium

相关主题的报道公司（非逐题归属）：字节跳动、百度

参考答案

在固定样本与验收门槛下比较上下文裁剪、缓存、模型路由和调用次数优化，统计每个成功任务成本而非单次便宜程度。质量与高风险指标不达门槛则回退。

得分点

  • 计入失败、重试与人工接管
  • 缓存带来源和权限版本

追问：少用大模型后更多任务需要人工，真的更便宜吗？

易错点：不能只报告 token 减少而省略成功率下降。

面经主题线索：INT-2bfa666e65（B：曾定位公开原帖）；INT-15d1d6b299（B：曾定位公开原帖）

103. RAG 延迟偏高时，怎样在召回规模、重排和生成之间确定优先优化项？

题目 ID：Q-10c2be69fb87 · 编辑难度：hard

相关主题的报道公司（非逐题归属）：拼多多

参考答案

先分解检索、重排和生成占比，再对候选数、索引策略、批处理、缓存及条件式重排做消融。设置证据质量最低线，优化关键路径并观察尾延迟和数据新鲜度。

得分点

  • 保持相同任务与最终上下文预算
  • 别让缓存绕过权限

追问：重排最快但召回不足时该先改哪里？

易错点：把 Top-K 降到很小可能只是把延迟换成错误。

面经主题线索：INT-a896abf415（C：仅聚合线索）

答案机制资料：BM25：Elasticsearch similarity settings: BM25；RRF：Reciprocal rank fusion in hybrid search

104. 服务响应慢但 CPU 利用率很低，你会先检查哪些等待环节？

题目 ID：Q-0032dbf7a79f · 编辑难度：medium

相关主题的报道公司（非逐题归属）：科大讯飞

参考答案

低 CPU 往往意味着在等网络、锁、磁盘、数据库连接、线程池或模型配额。先关联慢请求与排队/依赖耗时，再用线程栈、连接池和系统 I/O 指标确认，不能只看 CPU。

得分点

  • 比较正常基线与异常时段
  • 排除队列满或超时重试

追问：CPU 低但请求全堆积，如何判断是连接池还是远端慢？

易错点：加 CPU 不一定改善 I/O 或锁等待。

面经主题线索：INT-666456d67d（C：仅聚合线索）

答案机制资料：未单列外部机制资料，属于编辑推导，须结合具体契约独立验证。

105. 线上 CPU 突然占满时，如何从现象收敛到进程和具体调用链？

题目 ID：Q-978fa8246cfe · 编辑难度：medium

相关主题的报道公司（非逐题归属）：科大讯飞

参考答案

先定位异常进程与线程，再采样调用栈和 CPU/GC 指标，区分业务热循环、序列化、正则、GC、重试风暴或系统开销；关联发布和流量变化，复现后优化或回滚。

得分点

  • 保留故障证据
  • 生产诊断控制开销

追问：如何防止采样工具加重故障？

易错点：看到 CPU 高就扩容，可能只是暂时掩盖死循环。

106. 怀疑 Redis 依赖导致接口卡顿时，你会采集哪些证据？

题目 ID：Q-b8870e7eda34 · 编辑难度：hard

相关主题的报道公司（非逐题归属）：水滴公司

参考答案

关联客户端排队、连接池等待、网络 RTT、命令耗时、超时和服务端延迟；查看慢命令、热点大 key、CPU、内存、淘汰、持久化和复制状态。SLOWLOG 不覆盖所有网络等待。

得分点

  • 先量化 Redis 是否在关键路径
  • 诊断避免生产大范围重扫描

追问：为什么客户端很慢而 SLOWLOG 很干净？

易错点：不要把所有 Redis 慢问题都归因于单线程。

面经主题线索：INT-2599a140bd（C：仅聚合线索）

答案机制资料：REDISLATENCY：Redis latency troubleshooting

107. 工具执行并发增加后，怎样分析吞吐收益与共享状态风险？

题目 ID：Q-bc20e4b36884 · 编辑难度：hard

相关主题的报道公司（非逐题归属）：百度

参考答案

先验证工具彼此独立，再限制并发，测吞吐、排队、尾延迟、配额拒绝和共享资源冲突。并发会缩短独立分支的墙钟时间，但可能增加争用、重试和下游负载。

得分点

  • 关注幂等、取消及结果顺序
  • 并发上限按瓶颈调

追问：并发翻倍、吞吐不变但错误增加意味着什么？

易错点：不能只按工具数量开启无限并发。

面经主题线索：INT-eb93d2a417（B：曾定位公开原帖）

答案机制资料：REPLAY：LangGraph Graph API: re-execution and idempotency

108. 工具描述占满提示词预算时，怎样减少输入又保证正确路由？

题目 ID：Q-500777713c82 · 编辑难度：hard

相关主题的报道公司（非逐题归属）：字节跳动

参考答案

按权限和业务域筛选工具，再检索少量候选，用简短区分性描述初选，按需加载完整 schema。为近义工具和长尾任务测路由覆盖，并提供有界的扩展或澄清路径。

得分点

  • 缓存目录与版本绑定
  • 把“工具没召回”计入失败

追问：精简后模型选错相似工具怎么定位？

易错点：只看 prompt 长度下降，不足以证明优化有效。

面经主题线索：INT-c233db2a53（B：曾定位公开原帖）

答案机制资料：MCPTOOLS：MCP tools
