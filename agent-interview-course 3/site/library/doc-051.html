109. 说明进程与线程在资源共享、创建和上下文切换上的差异。

题目 ID：Q-2e2926af96c9 · 编辑难度：medium

相关主题的报道公司（非逐题归属）：字节跳动、水滴公司

参考答案

进程通常拥有独立虚拟地址空间，线程共享所在进程的地址空间、文件等资源但各有栈和执行状态；进程也可显式共享内存。创建与切换成本取决于系统和负载，不能只背固定倍数。

得分点

  • 解释共享带来的同步和故障传播
  • 区分用户态任务与内核线程

追问：线程崩溃为何可能影响整个进程？

易错点：线程不等于没有独立栈，也不是完全不消耗调度资源。

面经主题线索：INT-f135ac968c（C：仅聚合线索）；INT-2599a140bd（C：仅聚合线索）

答案机制资料：未单列外部机制资料，属于编辑推导，须结合具体契约独立验证。

110. 为本机多个进程交换数据，你会如何选择 IPC 机制并说明约束？

题目 ID：Q-9dd3b8718e26 · 编辑难度：medium

相关主题的报道公司（非逐题归属）：字节跳动、水滴公司

参考答案

单向字节流可用管道，双向本机服务可用 Unix socket，大数据低拷贝可考虑共享内存配合同步；消息队列适合有消息边界的交互。按吞吐、隔离、权限和生命周期选型。

得分点

  • 共享内存还需定义数据格式和一致性
  • 考虑进程退出清理

追问：零拷贝是否意味着完全没有同步开销？

易错点：不能只说“共享内存最快”而忽略竞态与维护成本。

111. 一次系统调用为什么涉及用户态和内核态，相关开销从哪里产生？

题目 ID：Q-9a9237cbd04e · 编辑难度：medium

相关主题的报道公司（非逐题归属）：字节跳动

参考答案

系统调用通过受控入口从用户权限切到内核权限，内核检查参数并完成特权操作后返回。开销包括入口/返回、校验、可能的数据复制及实际工作；不一定发生进程调度切换。

得分点

  • 区分权限模式切换和任务上下文切换
  • 说明阻塞调用的附加成本

追问：每次系统调用是否都会切换到另一个线程？

易错点：不能把用户/内核切换直接等同于进程切换。

面经主题线索：INT-f135ac968c（C：仅聚合线索）

答案机制资料：未单列外部机制资料，属于编辑推导，须结合具体契约独立验证。

112. TCP 建立连接的握手各解决什么问题，为什么不能简单省略？

题目 ID：Q-19b818f8d610 · 编辑难度：medium

相关主题的报道公司（非逐题归属）：字节跳动、水滴公司

参考答案

SYN 和 SYN+ACK 交换双方初始序列号，最后 ACK 确认对端序列号，建立可双向可靠传输的状态，也降低旧重复报文造成错误建连的风险。还需区分握手状态与应用可用。

得分点

  • 按两端状态和序号解释
  • 说明第三次 ACK 丢失的处理

追问：第三个包能否携带数据？

易错点：不要说“两次握手绝对无法传任何数据”，要说明规范与可靠性问题。

面经主题线索：INT-f135ac968c（C：仅聚合线索）；INT-2599a140bd（C：仅聚合线索）

答案机制资料：TCP：RFC 9293: Transmission Control Protocol

113. 从执行 curl 到收到响应，请沿客户端、网关、服务端解释完整网络路径。

题目 ID：Q-6cfd22c7238f · 编辑难度：medium

相关主题的报道公司（非逐题归属）：字节跳动

参考答案

先声明以 HTTPS/HTTP1.1 over TCP 为例：解析域名，路由选下一跳并完成链路寻址，经交换机/路由器到服务端，完成 TCP 与 TLS 后传 HTTP，再原路或按路由返回并处理响应。

得分点

  • DNS、ARP、连接可命中缓存
  • HTTP3使用QUIC，NAT仅在有配置时发生

追问：首次请求和复用连接分别省掉什么？

易错点：不是每次请求都重新 DNS、ARP 和建连。

面经主题线索：INT-04666050b7（C：仅聚合线索）

答案机制资料：TCP：RFC 9293: Transmission Control Protocol

114. 同网段和跨网段访问时，ARP 在请求链路中承担什么作用？

题目 ID：Q-8314d289eb14 · 编辑难度：medium

相关主题的报道公司（非逐题归属）：字节跳动

参考答案

IPv4 先按路由选择下一跳；目标在直连网段时 ARP 查询目标链路地址，否则通常查询网关的地址，IP 包目的地址仍是远端。每跳重新封装链路头；IPv6 用 NDP 而非 ARP。

得分点

  • 路由查找优先于简单套“默认网关”
  • ARP 作用范围是本地链路

追问：网关与目标都没有 ARP 缓存时如何交互？

易错点：不能对互联网上任意远端 IP 直接在本地做 ARP。

面经主题线索：INT-04666050b7（C：仅聚合线索）

答案机制资料：未单列外部机制资料，属于编辑推导，须结合具体契约独立验证。

115. 不依赖消息中间件，如何实现支持任务提交、状态查询和结果读取的异步服务？

题目 ID：Q-ccde26b7c0fe · 编辑难度：hard

相关主题的报道公司（非逐题归属）：字节跳动

参考答案

提交接口先将任务持久化并返回 task ID，Worker 用事务领取待执行任务并持有租约；状态查询读取状态和结果引用。失败支持有界重试、超时恢复、取消及幂等提交。

得分点

  • 例如数据库队列表配条件更新/行锁
  • 业务副作用仍需幂等

追问：Worker 领取后提交结果前宕机怎么办？

易错点：没有 MQ 不等于不能异步，也不等于数据库任务队列天然 exactly-once。

面经主题线索：INT-f135ac968c（C：仅聚合线索）

答案机制资料：STATE：LangGraph persistence；REPLAY：LangGraph Graph API: re-execution and idempotency

116. 配置 Java 线程池时，核心参数和拒绝策略应怎样结合业务负载决定？

题目 ID：Q-55c49ddc4952 · 编辑难度：medium

相关主题的报道公司（非逐题归属）：水滴公司

参考答案

说明核心/最大线程数、保活时间与单位、阻塞队列、线程工厂和拒绝策略。ThreadPoolExecutor 通常先扩到核心数，再入队，队列满后扩到最大数，仍无法接收才拒绝；结合等待比例和实测调参。

得分点

  • 有界队列配合背压
  • 解释 CallerRuns 对调用方延迟的影响

追问：无界队列为什么可能让最大线程数形同虚设？

易错点：DiscardOldest 丢的是队列中最旧等待任务，不是正在运行的任务。

面经主题线索：INT-2599a140bd（C：仅聚合线索）

答案机制资料：POOL：Java 21 ThreadPoolExecutor

117. 比较悲观锁、CAS 和 volatile 各自解决的问题，避免把可见性等同于原子性。

题目 ID：Q-51d1b383e987 · 编辑难度：medium

相关主题的报道公司（非逐题归属）：水滴公司

参考答案

锁可保护多步临界区及不变量；CAS 适合基于预期值的原子更新，竞争时可能重试并有 ABA 等问题；volatile 提供相应可见性/有序性，但 i++ 仍不是原子操作。

得分点

  • 把可见性、原子性和互斥分开
  • 跨字段更新考虑锁或事务

追问：高竞争下自旋为什么可能比阻塞更差？

易错点：不要声称声明 volatile 就能让容器或复合业务线程安全。

面经主题线索：INT-2599a140bd（C：仅聚合线索）

答案机制资料：JMM：Java Language Specification 21, threads and locks

118. HashMap 与 ConcurrentHashMap 分别适用于什么并发场景，为什么？

题目 ID：Q-757e0e71a723 · 编辑难度：medium

相关主题的报道公司（非逐题归属）：SHEIN、九方智投

参考答案

HashMap 不保证并发修改安全；ConcurrentHashMap 提供并发映射操作和相应可见性，可使用 putIfAbsent/compute 等表达特定原子更新。get 后再 put 的任意组合仍不自动原子。

得分点

  • CHM 不允许 null 键值
  • 别在映射更新回调里做不可控长阻塞

追问：遍历并发映射是否得到同一时刻的完整快照？

易错点：线程安全容器不能替代跨多个键的业务事务。

面经主题线索：INT-024a0e7447（C：仅聚合线索）；INT-5c781adab9（C：仅聚合线索）

答案机制资料：CHM：Java 21 ConcurrentHashMap；JMM：Java Language Specification 21, threads and locks

119. 删除旧缓存后又被并发请求写回旧值，怎样推导并处理这种竞争？

题目 ID：Q-fc9a5a4a6af4 · 编辑难度：hard

相关主题的报道公司（非逐题归属）：网易

参考答案

先画时间线：旧读在更新前开始，更新后删缓存，旧读随后把旧值写回。可通过版本水位/失效标记拒绝旧回填，配合 outbox/CDC 重试失效与 TTL 兜底；强一致读取走权威存储。

得分点

  • 缓存为空也需考虑旧读
  • 说明一致性窗口与代价

追问：延迟双删为何不能在任意调度下严格保证正确？

易错点：“先改库再删缓存”不是所有竞态下的强一致证明。

面经主题线索：INT-02e3d8f7b6（B：曾定位公开原帖）

答案机制资料：FENCE：How to do distributed locking, Martin Kleppmann

120. 用 Redis 实现令牌桶时，如何保证并发请求下的扣减语义？

题目 ID：Q-112e3e51d1a3 · 编辑难度：hard

相关主题的报道公司（非逐题归属）：字节跳动

参考答案

单次原子脚本读取桶状态、计算已补充令牌、判断并扣减，再写回时间和余额及合理过期时间；检查时间回拨，按租户选 key。Redis Cluster 中相关 key 需位于同一槽。

得分点

  • 脚本短小避免阻塞
  • 区分单节点原子性与故障切换后的全局保证

追问：Redis 不可用时是拒绝还是降级放行？

易错点：客户端分开执行 GET/计算/SET 会在并发下超发。

面经主题线索：INT-e52c427938（C：仅聚合线索）

答案机制资料：REDISATOMIC：Redis programmability and atomic script execution

150. 复盘一次生产内存问题时，如何区分工程缺陷与 JVM 参数问题并证明修复有效？

题目 ID：Q-5ed4f2c12061 · 编辑难度：hard

相关主题的报道公司（非逐题归属）：58同城

参考答案

先区分堆、直接/本地内存、线程、缓存或容器限制问题，关联GC、分配速率、对象存活和RSS；用受控快照/剖析找保留链或泄漏路径。修复后以相同负载观察长时间稳态。

得分点

  • 调整堆参数不代替修泄漏
  • 生产转储需评估停顿、磁盘与敏感数据

追问：堆使用稳定但RSS一直涨说明什么？

易错点：没有真实生产证据时，应给排查方案而不是杜撰事故和JVM调参效果。

面经主题线索：INT-NC-941138590514356224（B：曾定位公开原帖）

答案机制资料：未单列外部机制资料，属于编辑推导，须结合具体契约独立验证。
