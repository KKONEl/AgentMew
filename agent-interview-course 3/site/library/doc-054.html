13. 模型生成的工具名或参数不合法时，请设计校验、纠错和终止链路。

题目 ID：Q-51b911586a74 · 编辑难度：medium

相关主题的报道公司（非逐题归属）：字节跳动、海康威视

参考答案

先用允许的工具目录和 schema 校验动作，再校验身份、租户、业务前置条件及预算。可纠正的格式错误反馈给模型做有限次修复；未通过校验前不得调用真实工具。

得分点

  • 为调用绑定唯一 ID
  • 区分模型参数错误、工具错误与执行结果未知

追问：修复参数会不会改变用户原意？

易错点：不要无限重试，也不要默默删掉高风险参数来“修好”请求。

面经主题线索：INT-2bfa666e65（B：曾定位公开原帖）；INT-e363eb73e2（B：曾定位公开原帖）

答案机制资料：MCPTOOLS：MCP tools

14. 工具目录从十个增长到上千个后，怎样选择候选工具并控制描述长度？

题目 ID：Q-6c9c363bd7ee · 编辑难度：hard

相关主题的报道公司（非逐题归属）：字节跳动、百度

参考答案

按角色、权限和业务域预筛工具，再检索少量候选描述给模型；选中后按需加载完整 schema 并复核权限。缓存目录需版本化，评测检索覆盖率及端到端成功率。

得分点

  • 候选不足时允许有界扩展
  • 敏感工具不因语义相似就暴露

追问：正确工具没有进入候选集怎么办？

易错点：只缩短描述而不测路由召回，可能把成本优化成能力退化。

面经主题线索：INT-2bfa666e65（B：曾定位公开原帖）；INT-77a1694ccd（C：仅聚合线索）

答案机制资料：MCPTOOLS：MCP tools

15. 把已有 HTTP 接口接入 MCP，你认为新增了哪些协议层职责？

题目 ID：Q-c0aba57ad5cb · 编辑难度：medium

相关主题的报道公司（非逐题归属）：网易、迅雷

参考答案

MCP 不只是把 URL 改名：要实现规定版本的 JSON-RPC 方法、工具发现与调用契约、错误表达、传输和能力协商，并连接业务鉴权。HTTP 服务仍负责真实业务及授权。

得分点

  • 区分协议错误与工具业务错误
  • 按已部署版本实现，不混用握手与传输代际

追问：本地 stdio 与远程 HTTP 的身份边界相同吗？

易错点：MCP 本身不保证模型会选对工具，也不自动提供业务权限。

面经主题线索：INT-e123cde6cf（B：曾定位公开原帖）；INT-6784717d92（C：仅聚合线索）

答案机制资料：MCPTOOLS：MCP tools；MCPVERSION：MCP versioning and legacy initialization compatibility

16. 工具权限应该在什么位置校验，哪些操作必须先经人工确认？

题目 ID：Q-a6943ce6f660 · 编辑难度：medium

相关主题的报道公司（非逐题归属）：九方智投

参考答案

权限应在实际执行入口校验，身份来自可信会话而非模型参数。删除、支付、外发、跨租户访问等动作按风险策略审批，审批绑定具体资源、参数、版本、有效期和执行主体。

得分点

  • 规划时预检，执行前再检
  • 参数变化后重批

追问：审批后权限或目标资源变了怎么办？

易错点：不要只在 UI 按钮上限制权限。

面经主题线索：INT-fef75911f3（C：仅聚合线索）

答案机制资料：MCPTOOLS：MCP tools；INTERRUPT：LangGraph interrupts and idempotent side effects

17. 为什么工具参数通过结构校验后，仍需要业务权限与语义校验？

题目 ID：Q-02d17784d3c7 · 编辑难度：hard

相关主题的报道公司（非逐题归属）：vivo

参考答案

Schema 仅证明结构符合约定，不能证明用户有权操作该资源，也不能证明金额、状态或依赖条件合理。执行前需做对象级鉴权、业务约束和状态版本检查。

得分点

  • 租户身份由服务端注入
  • 将语义校验放在与写入一致的事务边界

追问：通过校验后到真正提交前状态变了怎么办？

易错点：字符串是合法 ID，不代表它属于当前用户。

面经主题线索：INT-4aea8e37ae（B：曾定位公开原帖）

答案机制资料：MCPTOOLS：MCP tools

18. 同一功能何时应该提供为 Tool，何时更适合封装成 Skill？

题目 ID：Q-c93845e54cf5 · 编辑难度：medium

相关主题的报道公司（非逐题归属）：百度

参考答案

Tool 适合边界清晰、输入输出可验证的能力；Skill 适合把领域知识、步骤和多个工具组织成可复用任务方法。具体产品对 Skill 的定义有差异，应先声明使用的语义。

得分点

  • Skill 不替代底层工具授权
  • 给出同一业务的能力层和任务层例子

追问：Skill 是否一定是一个独立 Agent？

易错点：不要把 Skill 当成 MCP 协议里的通用同义词。

面经主题线索：INT-77a1694ccd（C：仅聚合线索）

答案机制资料：GRAPH：LangGraph: Workflows and agents；MCPTOOLS：MCP tools

19. 为多种 MCP 传输方式做适配时，连接生命周期和会话状态如何处理？

题目 ID：Q-dec27ddf3ef1 · 编辑难度：hard

相关主题的报道公司（非逐题归属）：网易

参考答案

先标明协议版本。stdio 管子进程、消息通道及退出，日志不能污染协议输出；HTTP 管连接和请求。2026-07-28 版本取消协议会话与独立 GET 流；旧版可有会话，应用任务状态应独立持久化。

得分点

  • 按版本区分连接与应用任务
  • 不要把网络重连当任务恢复

追问：旧客户端携带会话头时如何处理？

易错点：不能把 2025 版 Mcp-Session-Id 行为背成所有版本通用规则。

面经主题线索：INT-02e3d8f7b6（B：曾定位公开原帖）

答案机制资料：MCPHTTP：MCP Streamable HTTP, revision 2026-07-28；MCPCHANGE：MCP changelog: sessions and standalone GET stream removal

20. 协议版本不一致时，客户端如何识别能力差异并做兼容性处理？

题目 ID：Q-d1d081ab44dd · 编辑难度：hard

相关主题的报道公司（非逐题归属）：网易

参考答案

锁定受支持的版本与能力矩阵，并按规范探测现代服务或兼容旧式 initialize 流程。仅在规定错误语义下回退；已识别的版本不支持错误应重试受支持版本，而非盲目降级。

得分点

  • 缓存探测结果并可失效
  • 为旧版、当前版及不兼容组合做契约测试

追问：无共同支持版本时应如何向用户报错？

易错点：“能连上 HTTP”不等于协议与能力兼容。

面经主题线索：INT-02e3d8f7b6（B：曾定位公开原帖）

答案机制资料：MCPVERSION：MCP versioning and legacy initialization compatibility；MCPCHANGE：MCP changelog: sessions and standalone GET stream removal

21. 请比较 SSE 与 Streamable HTTP 在实际接入中的差异，而不只背概念。

题目 ID：Q-c32226af0589 · 编辑难度：medium

相关主题的报道公司（非逐题归属）：网易

参考答案

SSE 是服务器向客户端发送事件的编码/推送机制；Streamable HTTP 是 MCP 的 HTTP 传输绑定，可以返回 JSON 或 SSE。2026-07-28 不再有旧式独立 GET 流和协议会话，需明确比较哪一版。

得分点

  • 区分通用 SSE 与旧 MCP HTTP+SSE
  • 分别验证请求、流结束和异常处理

追问：断流后是重发请求还是查询业务结果？

易错点：两者不是同层概念，Streamable HTTP 也不等于“完全不用 SSE”。

面经主题线索：INT-02e3d8f7b6（B：曾定位公开原帖）

答案机制资料：MCPHTTP：MCP Streamable HTTP, revision 2026-07-28；MCPCHANGE：MCP changelog: sessions and standalone GET stream removal

22. 依赖工具暂时不可用时，如何在替代工具、降级回答与任务失败之间选择？

题目 ID：Q-5f7009aee6de · 编辑难度：medium

相关主题的报道公司（非逐题归属）：快手、海康威视

参考答案

先看工具是否可替代、操作是否产生副作用以及任务是否强依赖结果。只读能力可切换等价来源；关键写入结果未知时先查询或对账；无法安全完成则保存状态并说明阻塞。

得分点

  • 退避与熔断受总预算约束
  • 降级内容明确标注缺失

追问：替代工具返回的语义与原工具一致吗？

易错点：不要用编造结果维持表面成功率。

面经主题线索：INT-2706b0f563（B：曾定位公开原帖）；INT-e363eb73e2（B：曾定位公开原帖）

答案机制资料：REPLAY：LangGraph Graph API: re-execution and idempotency；MCPTOOLS：MCP tools

23. 多个工具允许并行调用时，怎样表达依赖关系并合并失败结果？

题目 ID：Q-cdbe3279ea13 · 编辑难度：hard

相关主题的报道公司（非逐题归属）：百度

参考答案

用依赖图表达先后关系，只并行互不依赖且资源不冲突的步骤。每个调用独立记录 ID、状态和结果，汇总层按任务语义决定全有全无、部分成功或补偿。

得分点

  • 限制并发与共享资源写入
  • 处理取消及未知副作用

追问：一个分支成功、另一个失败后能否重跑整个节点？

易错点：Promise.all 一类等待工具并不自动解决事务一致性。

面经主题线索：INT-eb93d2a417（B：曾定位公开原帖）

答案机制资料：REPLAY：LangGraph Graph API: re-execution and idempotency；STATE：LangGraph persistence

24. 一个请求从意图路由到 Skill 再到工具调用，哪些中间结果需要可观测？

题目 ID：Q-63abdd15fa70 · 编辑难度：hard

相关主题的报道公司（非逐题归属）：美团

参考答案

记录请求/任务 ID、路由版本、候选工具、Skill 版本、动作参数摘要、策略与审批、调用结果、耗时用量及最终验收。敏感内容脱敏并限制访问；无需存储模型私有思维链。

得分点

  • 跨阶段关联 trace 与业务回执
  • 区分提议、执行和已提交结果

追问：如何从低分任务回溯到首次出错的阶段？

易错点：日志很多但缺少关联 ID，依然无法形成证据链。

面经主题线索：INT-77ca6f4ba2（C：仅聚合线索）

答案机制资料：STATE：LangGraph persistence；MCPTOOLS：MCP tools
