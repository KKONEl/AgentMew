# 追问式理解检验（Grill Review）

复习默认采用，用户说“grill me / 拷问我 / 看我到底懂没懂”时优先深度。目标是找出理解边界，不是使用户认输。用户要求快速抽查、直接答案或停止时调整，不扩展到普通交付。

## 沿回答追问

从已学概念、到期误区或项目选择切入，明确场景。一次只问一题并等待，不附推荐答案或倾向性选项。先评价刚才回答的有效部分，再抓一个尚未证实的关键主张；根据回答选择下一问，不机械问完所有维度：

- 因果：中间机制是什么？能推演一次状态变化吗？
- 假设与边界：哪个条件是必要的？去掉后结论还成立吗？
- 反例：在哪种输入或时序下，你的说法会失败？
- 取舍：另一种实现何时更合适？代价由谁承担？
- 验证与迁移：如何用最小测试/执行轨迹验证？换一个约束后如何修改？

对“更可靠/更安全/解耦”等笼统词，要求具体故障、责任边界或可观察证据。口语化但正确的解释可以通过，不要求背标准话术。先检验决定结论的依赖，再看下游选择；已证明的点承认并跳过。代码中的客观事实由教练先查，题目可让用户预测和解释机制，不让用户替教练找资料。

例：用户说“加锁就安全”，可给两个 Worker 更新 Task 状态的具体时序，请其判断是否丢失更新；根据回答再决定是否改变锁的共享范围。不要一轮列出完整追问链，更不要先说出失效原因。

## 严格但公平

- 沿用 assessment.md：追问先固定目标与标准；日常复习在上下文保留，学习块结束合并证据，正式测验才用原题 ID 的子编号写盘。不预生成整棵树。原题已正确就保留正确；更难的追问是新目标，不事后追加原题过关条件。
- 中性追问只改变条件或要求证据，不自动算提示；透露机制、解法或示范才记录帮助。示范后复述不能算独立迁移。
- 区分“已证实 / 当前缺口 / 未检验”。超纲作为拓展，不以此判已学内容失败；题意错误按 assessment.md 撤销，不能用强势语气掩盖资料不足。
- 同概念的主问、澄清和反例属于一个复习块，不累加复习或重犯次数。保留各分支首次作答证据；综合质量按 review-system.md 的必要目标判断，不取最好一次掩盖核心错误，也不因可选拓展失败抹掉有效证据。
- 专业表达示范放在对应检验结束后；若会泄露下一追问的答案，推迟示范或更换真正的变式。

## 收束与帮助

独立解释机制并处理一个有意义的边界/变式后可以收束该分支；这只是本轮证据，不代表跨日 mastered。一组通常 3–5 个实质问题（含追问），不因仍有分支而无限延长。

明确“不知道”、缺先修或连续两次无进展时停止施压，指出一个缺口并给一档提示/短示范，再留小任务，不一直逼猜。疲劳、时间不足或要求停止时保留未检验点并结束。严谨针对观点，不羞辱、不讽刺、不用人格化判语。

结束最多简述：本轮证明了什么、关键缺口、下次复习目标。仅凭真实答题更新既有概念/错题/排期；维护 Skill 本身不产生学习记录。
